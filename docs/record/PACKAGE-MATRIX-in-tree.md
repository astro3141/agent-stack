## Findings

1. **Promotion candidate — X1 step boilerplate**: all four packages hand-roll `RUN`/`WS`/settings/emit-JSON (write.py:9-10, execute.py:12-22, novel_stage.py:16-27, r_stage.py:15-21), and hello-lane's copy is wrong (`AGENTSTACK_WORKSPACE_ROOT`, undefined anywhere in the stack). A `stack/steps/step.py` helper (`ws()`, `out()`, refuse()) would remove the one P1 violation that exists only because the default happens to be `/ws`.
2. **Promotion candidate — X10b/X10c result schema**: the agent-step output block is copied into every workflow YAML (auto ×2, research-r via anchor, novel ×4), and auto/execute.py:42-66 re-implements agent_task.py:155-189's flattening. One shared schema fragment or a documented `agent_task` output contract would delete ~80 YAML lines and one Python duplicate.
3. **Promotion candidate — X2/X10a artifact binding**: novel (novel_stage.py:31-36, :134, :147-165) and research-r (r_stage.py:23,39; r-review.md:18) both hash artifacts and check that a later result is "about" the hash of a frozen input. The receipt already carries `context` and per-member sha256; a generic "verify receipt/result against frozen artifact" helper is the natural home.
4. **auto bypasses the Execution capability (C3 OWN)**: execute.py calls run-agent.mjs directly instead of agent_task.py, so it loses `produced`/`produced_stale` detection (agent_task.py:123-142), the login-refresh retry (:144-153), `{WS}` prompt files, and `mcp_principal`. It is the only package with a workspace of its own shape (`/ws/<run>-<provider>`, execute.py:21-22), i.e. a P1 deviation the recorder/panel do not resolve.
5. **C4 declared but not used (auto, research-r)**: both manifests require `tool_rights` yet pass no principal to the call and declare no principals.yaml; the write is governed only by the adapter's default credential. Either drop the requirement or name a principal.
6. **Unread manifest keys**: `requires.principals` (novel/manifest.yaml:8) and `requires.host_paths` (research-r/manifest.yaml:8) are read by nothing in stack/ (grep across stack, scripts, docs: no reader). research-r's hard dependency on the `/research` mount (compose.poc.yaml:118) is therefore unchecked at start; r_stage.py `in`/`review` then die with a traceback (P2/P5 violation) instead of a refusal.
7. **research-r drops an execution from the record (C6)**: research-r.yaml:185 records only `propose.output`; the `review` model call (research-r.yaml:136) is never passed as `executions:` and no `evidence_file` is given, so MLflow shows one call and zero evidence items for a two-call run. Also P6: its fixture is an absolute host path (r_stage.py:27), not `fixtures/` or `handoff/`.
8. **novel P3 nuance**: one `REPEATABLE = "guarded"` covers three subcommands (novel_stage.py:15); `stage` deletes draft/reviews on repeat (:45-49), which is "no"-with-destruction, not guarded. No package in this set has a true external effect, so the "ask the remote" half of P3 is exercised by none of them.
9. **X6 controls boundary is inverted for novel, absent for auto/research-r**: stack/trial_controls.py imports packages/novel/steps/novel_stage.py (:77, :307, :721, :815) and stack/cases/novel-shape.jsonl carries novel's case set, so the platform's control file depends on a package's internals; meanwhile no control anywhere loads auto/steps or research-r/steps. No package has a controls.py, and nothing in stack/packages.py or run_workflow.py runs one if it existed.
10. **novel does not use admit_models.py (C1)**: novel-a admits via route.py on the profile's single candidate (novel-a.yaml:49) and relies on roles.py's per-role eligibility check; admit_models.py's own docstring names the multi-vendor review round as its reason to exist, yet no package here calls it. research-r's six `/research/stack/steps.py` steps also sit outside the `REPEATABLE` control glob (trial_controls.py:798-800).
